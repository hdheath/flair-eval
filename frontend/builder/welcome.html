Compare FLAIR runs side by side

flair-eval runs several FLAIR versions, branches or settings on the same long-read data and puts the results in one report: isoform categories against your annotation, junction novelty, length distributions, and what changed between runs.

Set up a comparison See a demo report GitHub

Get started

  1. Install

    Nextflow (with Java 17+) runs the pipeline. The flair-eval command (Python 3.10+) checks your setup, writes the config files and launches runs.

    conda create -y -n nextflow -c conda-forge -c bioconda nextflow openjdk=17
conda activate nextflow
    pip install "flair-eval @ git+https://github.com/hdheath/flair-eval@main#subdirectory=cli"
flair-eval doctor

  2. Try the test data

    A small run on bundled test data shows the whole thing working before you point it at your own files.

    flair-eval run --test --outdir /private/groups/brookslab/$USER/flair-eval/dd_mm_yy_test

    On phoenix (UCSC PRISM) this submits the run as a SLURM job and prints the job id and log file. The report lands in <outdir>/report/report.html. --outdir is always required: use groups or warm-archive storage, not your home folder. Name folders date first (dd_mm_yy = today, e.g. 13_11_26_test).

  3. Describe your data

    Fill in the config builder, save samples.csv and runs.yaml if it asks for them, and run the command it gives you. Or answer a few questions in the terminal:

    flair-eval init
flair-eval run --outdir /private/groups/brookslab/$USER/flair-eval/dd_mm_yy_name

One sample? Skip the config files

One sample against three FLAIR versions. Each --flair token becomes a run. On phoenix, --genome hg38 picks the lab reference (GRCh38 + GENCODE v49 basic), so --gtf can be left out, and flair-eval run submits the job to SLURM for you.

flair-eval run --reads sample.fq.gz --genome hg38 \
  --flair 2.2.0,3.0.1,dev --outdir /private/groups/brookslab/$USER/flair-eval/dd_mm_yy_name

Other tokens pick a branch, a conda env or a container: see --flair tokens in the guide.

The same with plain Nextflow

On phoenix, run it inside an sbatch job and leave out -profile. Elsewhere, add -profile local,conda.

nextflow run hdheath/flair-eval -r main \
  --reads sample.fq.gz --genome hg38 \
  --flair 2.2.0,3.0.1,dev --outdir /private/groups/brookslab/$USER/flair-eval/dd_mm_yy_name

Extra FLAIR arguments: --flair_args='--stringent'. With plain nextflow run, keep the =: Nextflow reads --flair_args --stringent as two options.
