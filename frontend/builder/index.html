This is an example. Replace the paths with your own files; the command updates as you type.

Samples

One card per dataset: a reads file or an aligned BAM, and the genome to compare against. Use full paths.

Runs

One card per FLAIR configuration: which FLAIR, and which settings. Every run is applied to every sample.

Launch options

Results, the report and (on phoenix) Nextflow's work files. Use groups or warm-archive storage, not your home folder (about 100 GB quota). Type your user name in place of $USER.
On phoenix (UCSC PRISM) the command is flair-eval run: every step is a SLURM job, and FLAIR envs come from the shared lab cache.
conda builds each FLAIR version for you. flair-eval doctor shows what this machine has.
The report shows differences against this run (you can switch it in the report).

      flair-eval run checks your inputs, submits the run as a SLURM job and prints the
          job id and log file. Activate the Nextflow conda env first. Run it from the folder that holds the files, if any.
      
        
      On phoenix, run this inside an sbatch job, not on the login node (mustard).
      
      
      

      
      
        Before your first launch
        
        
          
      1. Install Java 17+ and Nextflow (once):
            
        conda create -y -n nextflow -c conda-forge -c bioconda nextflow openjdk=17 && conda activate nextflow
        2. 
          
      2. Install the flair-eval command and check this machine:
            
        pip install "flair-eval @ git+https://github.com/hdheath/flair-eval@main#subdirectory=cli"
        
            
        flair-eval doctor
        3. 
          
      3. Try the bundled test data first, then run the command above for your data:
            
        flair-eval run --test --outdir /private/groups/brookslab/$USER/flair-eval/dd_mm_yy_test
        4.
